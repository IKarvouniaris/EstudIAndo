Clase 02

Buenas prácticas (PEP8, docstrings) y manejo básico de errores

Transformar "código que funciona" en código legible, documentado y robusto ante errores — la base de calidad que se exige en toda la materia.

Conceptos clave

  • PEP 8: indentación de 4 espacios, snake_case para variables/funciones, CapWords para clases, imports agrupados al inicio.
  • PEP 257 / docstrings: triple comilla """...""", formato con Args, Returns, Raises; se accede con __doc__ y help().
  • Comentarios efectivos: explican el "por qué" (decisiones, reglas de negocio), no repiten el "qué" del código.
  • Excepciones: modelo try / except / else / finally; raise ... from exc para encadenar y conservar la causa original; excepciones propias heredando de ValueError/Exception.
  • E/S de datos: TXT (open()), CSV (csv.DictReader), JSON (json.load/json.dump); pathlib.Path en vez de strings sueltos.

Ejemplo

def cargar_configuracion(ruta: str) -> dict:
    """Carga configuración desde un archivo JSON.

    Args:
        ruta: Ubicación del archivo.
    Returns:
        Diccionario con la configuración.
    Raises:
        FileNotFoundError: Si la ruta no existe.
    """
    try:
        texto = Path(ruta).read_text(encoding="utf-8")
        return json.loads(texto)
    except FileNotFoundError as exc:
        raise FileNotFoundError(f"No existe: {ruta}") from exc
    except json.JSONDecodeError as exc:
        raise ValueError("El archivo no contiene JSON válido") from exc

Errores típicos

  • Nombres crípticos (cp(x) en vez de calcular_promedio(...)).
  • Comentarios que repiten el código en vez de explicar la decisión.
  • except: vacío o except Exception: pass que oculta bugs reales.
  • No cerrar archivos (olvidar with open(...)) ni fijar encoding="utf-8".

Clase 02.1

Manejo robusto de excepciones con JSON, TXT y CSV

Aplica el manejo de errores específicamente a leer/escribir archivos de datos: archivos faltantes, permisos, codificación, formatos inválidos y columnas ausentes.

Conceptos clave

  • Principios: fallar pronto, ser específico (capturar FileNotFoundError, PermissionError, json.JSONDecodeError, csv.Error, UnicodeDecodeError según el caso), cerrar recursos con with, registrar contexto con logging.exception().
  • Flujo recomendado: comprobar ruta → abrir seguro → parsear formato → validar estructura → convertir tipos → reportar/elevar.
  • Excepción de dominio reutilizable, ej. class DataFileError(Exception), que envuelve errores técnicos con raise ... from exc.
  • Capas de error distintas: lectura (FileNotFoundError, OSError), parseo (JSONDecodeError, csv.Error), validación (ValueError, KeyError), negocio (reglas propias).
  • Pandas como alternativa de alto nivel: pd.read_csv(on_bad_lines="error"), pd.to_numeric(errors="raise").

Ejemplo

def leer_ventas_csv(path: str) -> list[dict]:
    columnas = {"fecha", "producto", "region_ventas", "cantidad_ventas"}
    with Path(path).open("r", encoding="utf-8", newline="") as archivo:
        lector = csv.DictReader(archivo)
        if not lector.fieldnames or not columnas.issubset(lector.fieldnames):
            faltantes = columnas - set(lector.fieldnames or [])
            raise ValueError(f"Columnas faltantes: {faltantes}")
        return list(lector)

Antipatrones a evitar

  • Capturar todo con except Exception sin registrar ni reelevar.
  • Ignorar errores (except: pass o devolver [] como si nada hubiese pasado).
  • No validar columnas del CSV/JSON, asumiendo estructura perfecta.
  • Mensajes ambiguos ("Error" sin ruta, operación ni causa).

Clase 03

NumPy y Pandas: arreglos y datos tabulares

Los dos pilares técnicos del resto de la materia: cálculo vectorizado con NumPy y manipulación de datos tabulares con Pandas.

Conceptos clave

Clase 04

Preparación y movimiento de datos: índices, limpieza y formatos

Indexación avanzada, combinar datasets (concat vs. merge), un proceso de limpieza basado en diagnóstico, y persistencia en CSV/Excel/SQL/JSON. La clase más orientada a "pipeline reproducible".

Conceptos clave

  • concat apila (misma estructura, sin clave común) — merge relaciona (clave común, con cardinalidad 1:1/1:N/N:M). Son operaciones distintas que se confunden seguido.
  • merge: tipos de join inner/left/right/outer; validate="many_to_one"; indicator=True para ver qué coincidió.
  • Diagnóstico de calidad: df.isna().sum(), df.duplicated().sum(), df.nunique(), df.describe(include="all").
  • Nulos: eliminar vs. imputar (mediana robusta, moda para categorías); marcar con una columna bandera df['col_faltante'].
  • Tipos: pd.to_numeric(errors="coerce"), pd.to_datetime(errors="coerce", dayfirst=True), .astype("category").
  • Formatos de E/S: CSV (sep, decimal, parse_dates), Excel (sheet_name=None para todas las hojas), SQL (read_sql_query con parámetros — nunca concatenar), JSON (json_normalize para aplanar estructuras anidadas).
  • index=False al exportar, para no escribir el índice como columna.

Ejemplo

mascara = (ventas["importe_num"] >= 800) & ventas["producto"].isin(["A", "B"])
seleccion = ventas.loc[mascara, ["cliente_id", "producto", "importe_num"]]

ventas_clientes = ventas.merge(clientes, on="cliente_id", how="left",
                                validate="many_to_one", indicator=True)

df["importe_num"] = pd.to_numeric(
    df["importe"].str.replace("$", "", regex=False), errors="coerce"
)

Errores típicos

  • Confundir concat con merge, o alinear por índice con concat(axis=1) cuando los índices no son la misma entidad.
  • No validar la cardinalidad antes de un merge → explosión de filas por relación N:M inesperada.
  • No parametrizar consultas SQL (riesgo de inyección).
  • Olvidar index=False al exportar.

Clase 05

Visualización con Matplotlib

Traducir una pregunta analítica en una visualización correcta (tendencia, comparación, distribución, relación), con la interfaz Figure/Axes. Énfasis en comunicación honesta, no sólo en sintaxis.

Conceptos clave

  • Elección de gráfico según la pregunta: tendencia → líneas; comparación → barras (base en cero); distribución → histograma; relación → dispersión (no prueba causalidad).
  • Anatomía: Figure = lienzo completo, Axes = área de dibujo; fig, ax = plt.subplots(...).
  • Subgráficos múltiples: plt.subplots(n, m, figsize=...), indexado axes[i,j].
  • Ajuste lineal con np.polyfit(x, y, 1) para una recta de tendencia sobre un scatter.
  • Cierre: fig.tight_layout(), plt.show(), fig.savefig(..., dpi=...).

Ejemplo

fig, ax = plt.subplots(figsize=(8, 4))
ax.plot(meses, ventas, marker="o")
ax.set_title("Ventas mensuales"); ax.set_xlabel("Mes"); ax.set_ylabel("Unidades")
fig.tight_layout(); plt.show()

m = np.mean(df['minutos'])
plt.hist(df['minutos'], bins=np.arange(15,55,5), color='teal', edgecolor='white')
plt.axvline(m, color='red', linestyle='--', label=f'Media={m:.1f}')
plt.legend()

Errores frecuentes

  • Eje truncado (no empezar en cero) que exagera diferencias en barras.
  • Título genérico ("Ventas") en vez de uno que comunique el hallazgo.
  • Miles de puntos superpuestos en un scatter sin alpha (transparencia).
  • Confundir correlación con causalidad al interpretar una recta ajustada.

Clase 06

Visualización con Seaborn

Seaborn como interfaz estadística de alto nivel sobre Matplotlib, usada junto con Pandas: Pandas organiza → Seaborn visualiza → Matplotlib controla figura/exportación.

Conceptos clave

  • sns.heatmap(df.corr(), annot=True): cerca de +1/-1 = asociación lineal fuerte; cerca de 0 = poca asociación lineal (no independencia).
  • sns.boxplot() + sns.stripplot(): mediana, caja = rango intercuartílico, puntos externos = posibles atípicos.
  • sns.pairplot(hue=...): matriz de relaciones por pares — útil con pocas variables, lento con muchas.
  • Multivariado con un solo scatter: hue, size, style — una variable por canal visual, sin sobrecargar.
  • Exportación para informes: PNG (dpi=300) para web/Office, PDF/SVG (vectorial) para impresión.

Ejemplo

corr = df.select_dtypes("number").corr()
sns.heatmap(corr, annot=True, cmap="vlag", vmin=-1, vmax=1)

sns.boxplot(data=df, x="Curso", y="Nota", hue="Curso", legend=False)
sns.stripplot(data=df, x="Curso", y="Nota", color="black", alpha=.4)

sns.scatterplot(data=df, x="Horas", y="Nota", hue="Curso", size="Proyectos",
                 style="Curso", sizes=(40, 220), alpha=.78)

Errores típicos

  • Interpretar correlación ≈ 0 como "independencia" (sólo indica poca asociación lineal).
  • Confundir correlación con causalidad al leer un heatmap o regplot.
  • pairplot con demasiadas columnas: lento y difícil de leer.
  • Codificar más de una variable por canal visual sin criterio (color + forma + tamaño a la vez).

Clase 10

Estadística descriptiva, groupby y tablas dinámicas

Resumir datos con criterio: primero una «radiografía» con describe(), después centro y dispersión leídos juntos, y por último resúmenes por grupo (groupby) y tablas cruzadas (pivot_table). La idea de cierre de la clase: describir → agrupar → pivotar → decidir, y cada resumen tiene que responder una pregunta concreta.

describe(): la primera radiografía

  • Cantidad y centro: count son los valores no nulos (no las filas), mean es la media y el percentil 50% es la mediana.
  • Dispersión: std es el desvío estándar (muestral); 25% y 75% son Q1 y Q3, que encierran el 50 % central.
  • Extremos: min y max sirven para ver el rango y detectar valores imposibles o atípicos (una edad de 250, una venta negativa).
  • Sobre todo el DataFrame resume solo las columnas numéricas; sobre una columna (df["x"].describe()) resume esa Series. percentiles=[.1, .25, .5, .75, .9] pide otros cortes y .round(2) redondea.
import pandas as pd

df = pd.DataFrame({"edad": [34, 45, 52, 41, 63],
                   "presion_sistolica": [118, 132, 145, 128, 151]})

print(df["presion_sistolica"].describe())          # describe(), sin «s», de UNA columna
print("Mediana:", df["presion_sistolica"].median()) # median() con paréntesis
# count 5 · mean 134.8 · std 13.255 · min 118 · 25% 128 · 50% 132 · 75% 145 · max 151

Centro: media, mediana y moda

  • Media (mean()): suma / cantidad. Usa todos los datos, así que un extremo la «arrastra». En el ejemplo da 134,8.
  • Mediana (median()): el valor central de los datos ordenados (132). Solo depende de la posición, así que es robusta a outliers: si el 151 fuera 300, la media subiría a 164,6 y la mediana seguiría en 132.
  • Moda (mode()): el valor más frecuente. Sirve también para categorías y puede haber más de una: por eso mode() devuelve una Series, no un número.

Dispersión: cuánto se separan los datos

var() / std()Varianza (en unidades al cuadrado) y desvío estándar (en la unidad original, más fácil de interpretar). pandas usa la versión muestral: divide por n − 1 (ddof=1).
max() - min()Rango: toda la amplitud. Depende de los dos valores más extremos.
quantile(0.75) - quantile(0.25)IQR = Q3 − Q1: la amplitud del 50 % central. Robusto. quantile recibe una proporción entre 0 y 1.
std() / mean() * 100Coeficiente de variación (CV, en %): dispersión relativa. Sirve para comparar grupos con escalas o medias distintas.

Leer centro y dispersión juntos

  • Media ≈ mediana: distribución más o menos equilibrada.
  • Media > mediana: posible asimetría positiva (unos pocos valores altos tiran la media hacia arriba, típico de salarios o precios).
  • Media < mediana: posible asimetría negativa (valores bajos).
  • IQR chico: el centro está concentrado. Desvío alto: los valores se alejan del promedio.
  • Un punto aislado se investiga, no se borra automáticamente.

groupby: dividir, aplicar, combinar

Dividir las filas en grupos según una clave (ciudad, categoría, fecha), aplicar una función a cada grupo (suma, media, conteo…) y combinar los resultados en una Series o un DataFrame. La clave tiene que responder la pregunta: «¿cuánto vende cada ciudad?» se agrupa por ciudad.

datos = pd.DataFrame({"Ciudad": ["Bogotá", "Bogotá", "Cali", "Cali"],
                      "Categoria": ["Hogar", "Tecnologia", "Hogar", "Tecnologia"],
                      "Ventas": [1130, 850, 690, 790],
                      "Unidades": [3, 2, 1, 3]})

# una agregación; as_index=False deja la clave como columna normal
datos.groupby("Ciudad", as_index=False)["Ventas"].sum()

# varias métricas con nombre propio (named aggregation): nuevo_nombre=("columna", "función")
datos.groupby("Ciudad", as_index=False).agg(
    ventas_totales=("Ventas", "sum"),
    venta_promedio=("Ventas", "mean"),
    unidades_totales=("Unidades", "sum"),
    operaciones=("Ventas", "count"))

# dos claves: un grupo por cada combinación Ciudad × Categoria
datos.groupby(["Ciudad", "Categoria"], as_index=False).agg(ventas=("Ventas", "sum"))

Bogotá suma 1980 y Cali 1480. El resumen dice cuánto, no por qué: la pregunta siguiente es si la diferencia viene de más operaciones, más unidades o un precio promedio más alto.

pivot y pivot_table

  • pivot() solo reorganiza, no agrega. Cada combinación fila × columna tiene que ser única: si hay duplicados falla con ValueError: Index contains duplicate entries.
  • pivot_table() reorganiza y agrega: acepta aggfunc, fill_value, margins y varias claves. Regla práctica: si puede haber más de un dato por celda, pivot_table.
index¿Qué va en las filas?
columns¿Qué va en las columnas?
values¿Qué número va adentro de las celdas?
aggfuncSi hay varios datos para una celda, ¿cómo se resumen? "mean" (el valor por defecto), "sum", "count", "min", "max", "median", o una lista (["sum", "mean"]). No existe "average".
fill_value=0Rellena las combinaciones que no existen. Tiene que ser un número (0, no "0").
margins=TrueAgrega una fila y una columna All con el total general; margins_name="Total" la renombra.
clima = pd.DataFrame({"ciudad": ["A", "A", "B", "B"],
                      "estacion": ["Verano", "Invierno", "Verano", "Invierno"],
                      "temperatura": [29, 14, 31, 12]})

pd.pivot_table(clima, index="ciudad", columns="estacion",
               values="temperatura", aggfunc="mean", margins=True)
# estacion  Invierno  Verano   All
# A             14.0    29.0  21.5
# B             12.0    31.0  21.5
# All           13.0    30.0  21.5

Fila A × columna Verano = 29 (un solo dato). La columna All de A es su promedio anual: (14 + 29) / 2 = 21,5. La esquina All/All es el promedio de los cuatro datos. Para buscar el máximo de una columna, primero se saca la fila de totales (tabla.drop(index="All")): si no, el total gana siempre.

Faltantes en una tabla dinámica

  • Un dato faltante (None) se guarda como NaN: «no tengo el dato». No es cero: que no se midió la emisión de Energía en 2023 no significa que haya emitido 0.
  • Trampa: con aggfunc="sum" una celda que solo tenía NaN aparece como 0 (la suma de nada es 0). Para conservar el NaN: sum(min_count=1), «sumá solo si hay al menos un dato real».
  • Rellenar con 0 (fill_value=0) o con la mediana del grupo es una decisión que se justifica y se documenta.
emisiones = pd.DataFrame({"anio": [2022, 2022, 2023, 2023],
                          "sector": ["Energía", "Transporte", "Energía", "Transporte"],
                          "co2": [120.0, 80.0, None, 85.0]})

tabla = emisiones.pivot_table(index="sector", columns="anio", values="co2",
                              aggfunc=lambda s: s.sum(min_count=1))    # conserva el NaN
tabla["Total"] = tabla.sum(axis=1, min_count=1)      # axis=1: a lo largo de cada fila
# anio         2022  2023  Total
# Energía     120.0   NaN  120.0
# Transporte   80.0  85.0  165.0

groupby + apply: promedio ponderado

  • Promedio ponderado = Σ(valor × peso) / Σ(peso). Norte: (12000·2 + 18000·1) / 3 = 14000 (el simple daría 15000: la zona con más población pesa más).
  • agg resume una columna por vez. Cuando la cuenta necesita varias columnas del grupo (valor y peso), se usa groupby(...).apply(f): f recibe el mini-DataFrame de cada grupo. include_groups=False (plural, pandas 2.2) evita pasarle la columna de agrupación.
  • División por cero: si los pesos de un grupo suman 0, devolver np.nan (no 0). Si f devuelve una pd.Series con etiquetas, cada etiqueta se vuelve una columna.
import numpy as np

def promedio_ponderado(g):                       # g = mini-DataFrame de UNA región
    poblacion_total = g["poblacion"].sum()
    if poblacion_total == 0:
        pib = np.nan                             # no se puede ponderar
    else:
        pib = (g["pib_pc"] * g["poblacion"]).sum() / poblacion_total
    return pd.Series({"pib_ponderado": pib, "poblacion_total": poblacion_total})

resultado = df.groupby("region").apply(promedio_ponderado, include_groups=False)
#         pib_ponderado  poblacion_total
# Norte         14000.0              3.0
# Sur           15000.0              3.0

Caso integrador: de los registros al informe

df = pd.read_csv("ventas.csv")
df["Ventas"] = pd.to_numeric(df["Ventas"], errors="coerce")     # texto raro → NaN
df = df.dropna(subset=["Ciudad", "Categoria", "Ventas"])        # sin datos críticos
print(df["Ventas"].describe())
resumen = df.groupby("Ciudad", as_index=False).agg(
    total=("Ventas", "sum"), promedio=("Ventas", "mean"), dispersion=("Ventas", "std"))
tabla = df.pivot_table(values="Ventas", index="Ciudad", columns="Categoria",
                       aggfunc="sum", fill_value=0)
resumen.to_excel("resumen_ciudades.xlsx", index=False)
tabla.to_excel("ventas_por_categoria.xlsx")      # acá el índice (Ciudad) sí importa

Errores típicos

  • Promediar identificadores (el promedio de los DNI no significa nada) y confundir sum con count: count cuenta registros no nulos, sum suma valores.
  • Ignorar los NaN: count no los cuenta y sum los trata como 0.
  • Duplicar observaciones antes de agrupar (un merge mal hecho multiplica filas e infla los totales).
  • Usar pivot con duplicados → pivot_table con un aggfunc.
  • Método sin paréntesis (.mean devuelve el método, no el número), describes(), aggfunc="average", quantile(25), parámetros en singular (column=, value=).
  • No revisar grupos chicos: el promedio de un grupo de 2 datos no se compara igual que el de uno de 200.
  • Leer asociación como causalidad: que Bogotá venda más no dice por qué.

Clase 11

Valores atípicos, distribuciones y transformaciones

Detectar valores extremos (IQR, Z-score, gráficos), describir la forma de una variable y transformarla para comparar o modelar: normalizar, estandarizar, discretizar y crear variables nuevas. La idea central de la clase: transformar datos no es «maquillarlos»: es construir una representación más útil, reproducible y documentada.

Dónde entra en el flujo

Definir el problema → recolectar → limpiar → explorar → transformar → modelar → comunicar. El proceso es iterativo, y la pregunta guía frente a un valor raro es: ¿es un error, un evento raro válido o una señal importante?

Describir una variable

  • Centro: media (sensible a extremos), mediana (robusta ante sesgo), moda.
  • Dispersión: desvío estándar, cuartiles e IQR, rango, coeficiente de variación.
  • Forma: asimetría (hacia qué lado se estira la cola), curtosis (cuánto pesan las colas) y multimodalidad (varios «picos»: suele indicar varios grupos mezclados).
  • ¿Para qué modelar después? Predecir un valor (ventas, precio, consumo), clasificar observaciones (fraude o no, nivel de riesgo), explicar relaciones entre variables o detectar grupos y casos inusuales.

Un atípico no es automáticamente un error

Error de calidadUnidad equivocada, decimal perdido, sensor roto, duplicado o dato imposible.
Evento raro válidoUn paciente extremo, una crisis económica, un episodio ambiental, una transacción excepcional.
Señal de negocioFraude, falla, oportunidad, cambio de régimen o una población especial.

Nunca se elimina un valor solo porque un algoritmo lo marcó: primero se investiga contexto, fuente y consecuencia. En salud, la validación con el dominio es obligatoria. Para explorar: el histograma muestra la forma global y el boxplot resume mediana, cuartiles y extremos.

Detectar con IQR (regla de Tukey)

  • IQR = Q3 − Q1 (una resta, no una suma).
  • Es atípico lo que cae fuera de Q1 − 1,5·IQR y Q3 + 1,5·IQR. Es la misma regla con que el boxplot dibuja los puntos sueltos.
  • quantile() recibe una proporción (0.25), no un porcentaje: quantile(25) da ValueError. pandas interpola (por eso aparecen cuartiles como 13,5).
  • Para combinar condiciones en una Series: | («o») y & («y»), cada condición entre paréntesis. ~ invierte (~s.between(li, ls) = «fuera del rango»).
  • Por grupo: groupby(...).transform(lambda s: s.quantile(0.25)) devuelve el Q1 de su grupo en cada fila, alineado con el DataFrame.
pm25 = pd.Series([12, 14, 13, 15, 16, 14, 80])      # µg/m³
q1 = pm25.quantile(0.25)        # 13.5
q3 = pm25.quantile(0.75)        # 15.5
iqr = q3 - q1                   # 2.0
limite_inferior = q1 - 1.5 * iqr    # 10.5
limite_superior = q3 + 1.5 * iqr    # 18.5

atipicos = pm25[(pm25 > limite_superior) | (pm25 < limite_inferior)]   # el 80
# lo mismo, más corto:
atipicos = pm25[~pm25.between(limite_inferior, limite_superior)]

IQR, Z-score y métodos multivariados

IQRRobusto y simple; sirve para distribuciones sesgadas. Mira una variable por vez.
Z-scorez = (x − media) / desvío: cuántos desvíos se aleja un dato. Interpretable si la distribución es más o menos simétrica, pero sensible a los extremos: el propio atípico infla la media y el desvío.
MultivariadosPara varias variables a la vez: Isolation Forest, Local Outlier Factor o distancias robustas. Siempre con validación de dominio.

Transformaciones con scikit-learn

El preprocesamiento convierte los datos crudos en una representación más adecuada para el modelo. Todos los transformadores siguen el mismo patrón: fit aprende parámetros (mínimo y máximo, media y desvío, mediana e IQR) y transform los aplica; fit_transform hace las dos cosas.

MinMaxScalerx' = (x − mín) / (máx − mín): lleva a [0, 1]. Conserva el orden; un extremo comprime a todos los demás.
StandardScalerz = (x − media) / desvío: media 0 y desvío 1. Útil para métodos sensibles a la escala (k-NN, regresión logística).
RobustScalerUsa mediana e IQR: más robusto cuando hay extremos.
PowerTransformerBusca una distribución más parecida a la normal (reduce la asimetría).
KBinsDiscretizer / pd.cutPasan una variable continua a intervalos.
OneHotEncoderConvierte categorías en columnas numéricas 0/1.
from sklearn.preprocessing import MinMaxScaler

df = pd.DataFrame({"ingreso": [500, 1000, 1500]})
scaler = MinMaxScaler()
df["ingreso_norm"] = scaler.fit_transform(df[["ingreso"]])   # doble corchete: tabla 2D
#    ingreso  ingreso_norm
# 0      500           0.0
# 1     1000           0.5
# 2     1500           1.0

Regla práctica que se repite en toda la clase: el transformador se ajusta solo con los datos de entrenamiento (después se reutiliza el mismo objeto para prueba y producción). Si se ajusta con todo, información de la prueba «se filtra» al modelo: fuga de información. Se retoma en la clase 12.

Min-Max conserva el orden relativo; el Z-score expresa la distancia a la media en desvíos. Sirven, por ejemplo, para comparar PIB y desempleo, que tienen unidades y escalas muy distintas.

Discretizar con pd.cut

  • Cuándo conviene: reglas de negocio comprensibles, reportes por niveles de riesgo, relaciones no lineales simples, reducir ruido. Riesgo: perder información y crear cortes arbitrarios: los umbrales se justifican (criterio económico, normativa, OMS…).
  • bins son los bordes y labels los nombres: cantidad de labels = cantidad de bordes − 1. -np.inf / np.inf (o float("inf")) dejan abiertos los extremos.
  • right=True (por defecto) incluye el borde derecho: (a, b]. Con right=False son [a, b). include_lowest=True incluye el primer borde (el 0).
  • Pasá los argumentos con nombre: el tercer argumento posicional de pd.cut es right, no labels. pd.cut(x, bins, labels) no da error, pero devuelve intervalos en vez de nombres.
  • pd.qcut corta por cuantiles: grupos de tamaño parecido.
inflacion = pd.Series([1.2, 3.8, 7.1])
pd.cut(inflacion, bins=[-float("inf"), 2, 5, float("inf")],
       labels=["Baja", "Moderada", "Alta"])          # Baja, Moderada, Alta

df = pd.DataFrame({"peso_kg": [60, 78, 95, 52], "altura_m": [1.65, 1.75, 1.70, 1.60]})
df["imc"] = (df["peso_kg"] / df["altura_m"] ** 2).round(1)      # 22.0, 25.5, 32.9, 20.3
df["categoria"] = pd.cut(df["imc"], bins=[0, 18.5, 25, 30, 100],          # 5 bordes
                         labels=["Bajo", "Normal", "Sobrepeso", "Obesidad"],  # 4 nombres

Ingeniería de variables

  • Razones (deuda / ingreso), diferencias (consumo actual − histórico), interacciones (temperatura × carga), tiempo (hora, día, estación), agregados (media móvil, acumulado) y variables de dominio (IMC, energía por kilómetro).
  • Orden de las operaciones: ** se resuelve antes que * y /. IMC = peso / altura ** 2; peso / altura * 2 es un error lógico que no avisa.

from sklearn.preprocessing import StandardScaler

# en un proyecto real se separa train/test ANTES de ajustar el scaler

Series temporales: comparar contra una referencia móvil

En una serie con tendencia (el CO₂ atmosférico sube año a año), un Z-score global confunde la tendencia con una anomalía. Mejor: calcular una media móvil (rolling(12).mean()), restarla (el residuo) y estandarizar el residuo. Así se marca solo lo que se aparta de su contexto local. Antes de concluir, revisar cambios de instrumento, faltantes y el contexto físico.

media12 = co2.rolling(12).mean()                  # tendencia local de 12 meses
residuo = co2 - media12
z_local = (residuo - residuo.mean()) / residuo.std()
alerta = z_local.abs() > 3

¿Eliminar, transformar, limitar o conservar?

Error confirmadoCorregir desde la fuente o excluir dejando registro (trazabilidad).
Válido pero extremoConservar; usar un método robusto (mediana, RobustScaler) o una transformación.
Domina el modeloEvaluar logaritmo, winsorización (topear en un límite, como clip(li, ls)) o un modelo menos sensible.
Evento raro de interésConservar y modelarlo explícitamente.
Físicamente imposibleMarcar, investigar y aplicar validación de dominio.

Checklist antes de entregar: fuente documentada, unidades verificadas, faltantes y duplicados revisados; centro + dispersión + forma con gráfico; transformación sin fuga, con los parámetros guardados y reversible; supuestos explícitos, atípicos investigados e impacto explicado.

Errores típicos

  • Borrar atípicos automáticamente porque una regla los marcó.
  • q1 + q3 en vez de q3 - q1; quantile(25) en vez de quantile(0.25).
  • and/or con Series → &/| y paréntesis.
  • Ajustar el escalador con todos los datos antes de separar train y test (fuga de información).
  • Labels ≠ intervalos en pd.cut (5 bordes son 4 labels) y pasarlos sin nombre.
  • Min-Max con un extremo presente: todos los demás quedan apretados cerca de 0. Recortar antes o usar RobustScaler.
  • Z-score global en una serie con tendencia: marca la tendencia como anomalía.
  • IQR por grupo con muy pocos datos: con tres valores por grupo la regla casi nunca marca nada.

Clase 12

Flujo de trabajo y datasets integrados en Scikit-learn

El recorrido completo de un problema supervisado: cargar, explorar, preprocesar, separar en entrenamiento y prueba, entrenar y evaluar. Se practica con los datasets que trae scikit-learn (sin descargar archivos) y la clave de toda la clase es controlar qué información ve cada etapa y cuándo la ve.

Las seis etapas

1 Carga → 2 Exploración → 3 Preprocesamiento → 4 Train/Test → 5 Entrenamiento → 6 Evaluación. Cada etapa responde una pregunta distinta y saltear una vuelve los resultados difíciles de interpretar o reproducir. El flujo es iterativo: si la evaluación sale mal, se vuelve al preprocesamiento, a las variables o al algoritmo.

1. Carga: la matriz X y el vector y

  • X: las características o predictores (una columna por característica). y: la variable objetivo, lo que se quiere predecir. Cada fila es una observación.
  • Fuentes: CSV o Excel, bases de datos, APIs, sensores y registros.
  • Qué revisar al cargar: cantidad de filas y columnas, tipos de dato, nombres de variables, faltantes y duplicados.
  • En Iris, X son las cuatro medidas de cada flor e y es la especie.

2 y 3. Explorar y preprocesar

  • Limpieza: duplicados, errores, incoherencias y faltantes. Codificación: categorías a números. Escalado: variables en escalas comparables cuando el algoritmo lo necesita. Selección: quedarse con las variables relevantes.
  • Regla práctica: toda transformación que aprende parámetros (escalador, imputador) se ajusta solo con el conjunto de entrenamiento.

4. Separar entrenamiento y prueba

  • El conjunto de prueba simula datos nuevos que el modelo no vio. Lo habitual: 80 % entrenamiento, 20 % prueba (test_size=0.20).
  • Entrenamiento: se usa para ajustar el preprocesador y los parámetros del modelo. Prueba: se reserva para estimar si el modelo generaliza.
  • random_state=42: fija la semilla, así la división es siempre la misma y los resultados se pueden repetir y comparar.
  • stratify=y: conserva la proporción de cada clase en los dos conjuntos.
  • Evaluar con los mismos datos con que se entrenó da una visión demasiado optimista.
from sklearn.datasets import load_iris
from sklearn.model_selection import train_test_split
from sklearn.preprocessing import StandardScaler

iris = load_iris(as_frame=True)       # as_frame=True: devuelve DataFrame y Series de pandas
X, y = iris.data, iris.target         # (150, 4) y 3 clases de 50

X_train, X_test, y_train, y_test = train_test_split(
    X, y, test_size=0.20, random_state=42, stratify=y)    # el orden de salida importa

scaler = StandardScaler()
X_train_s = scaler.fit_transform(X_train)   # aprende media y desvío de TRAIN y transforma
X_test_s = scaler.transform(X_test)         # solo transform: usa lo aprendido en train

Fuga de información: si el escalador se ajusta con todos los datos antes de dividir, la media y el desvío ya «conocen» la prueba, y la evaluación deja de medir datos nuevos.

5. Entrenar: fit y predict

  • Modelo: una representación matemática que transforma entradas en predicciones. Entrenar es ajustar sus parámetros internos con X_train e y_train.
  • fit() aprende; predict() aplica lo aprendido a casos nuevos. El algoritmo no memoriza instrucciones: aprende patrones a partir de ejemplos etiquetados (aprendizaje supervisado).
  • Regresión logística: a pesar del nombre, se usa para clasificar. Estima la probabilidad de cada clase y asigna la más probable. max_iter=300 le da más iteraciones para converger.
from sklearn.linear_model import LogisticRegression
from sklearn.metrics import accuracy_score, confusion_matrix

model = LogisticRegression(max_iter=300)
model.fit(X_train_s, y_train)
y_pred = model.predict(X_test_s)
print(accuracy_score(y_test, y_pred))       # real primero, predicho después
print(confusion_matrix(y_test, y_pred))

6. Evaluar: ninguna métrica responde todo

accuracyProporción de predicciones correctas. Fácil de leer, pero engañosa si las clases están desbalanceadas. Un 95 % es 95 de cada 100 correctas en datos comparables, pero no dice qué tipo de error comete.
matriz de confusiónCruza clase real (filas) y predicha (columnas). La diagonal son los aciertos; fuera de ella, qué clases se confunden.
precisionDe los que el modelo marcó como positivos, ¿cuántos lo eran? Fiabilidad de los positivos predichos.
recallDe los positivos reales, ¿cuántos encontró? Capacidad de detectar.

Datasets integrados

load_iris()Clasificación multiclase: tres especies de flor a partir de cuatro medidas.
load_wine()Clasificación multiclase: tres tipos de vino según 13 variables químicas.
load_breast_cancer()Clasificación binaria (maligno / benigno) con características de núcleos celulares.

Ventajas: reproducibles, disponibles sin descarga, ideales para probar algoritmos, y traen datos, objetivo y metadatos (feature_names, target_names, DESCR).

Mejor práctica: Pipeline

Un Pipeline encadena el preprocesamiento y el modelo en el orden correcto. Al hacer fit ajusta cada paso con train; al hacer predict transforma la prueba con lo aprendido y predice. Ventajas: evita aplicar transformaciones distintas a train y test, facilita la validación cruzada y la búsqueda de hiperparámetros, y deja el flujo reproducible y legible.

from sklearn.pipeline import Pipeline

pipeline = Pipeline([("scaler", StandardScaler()),
                     ("model", LogisticRegression(max_iter=300))])
pipeline.fit(X_train, y_train)        # datos SIN escalar: el pipeline se encarga
y_pred = pipeline.predict(X_test)

Errores frecuentes y su corrección

  • Escalar antes de dividir → dividir primero y ajustar el escalador solo con train.
  • Evaluar sobre train → reservar test y reportar las métricas sobre datos no vistos.
  • Ignorar el desbalance → mirar la distribución de clases y sumar métricas (matriz, precision, recall).
  • Elegir solo por accuracy → analizar la matriz de confusión.
  • Probar muchas veces sobre test → ajustar con validación cruzada y dejar test para el final.
  • Cambiar datos sin documentar → registrar decisiones, semillas y transformaciones.
  • fit_transform sobre test: vuelve a aprender con la prueba. En test va solo transform.

Pregunta de cierre de la clase: si el modelo no generaliza, ¿qué etapa cambiarías primero? Normalmente se revisa el preprocesamiento y las variables antes que el algoritmo.

Clase 13

Regresión lineal simple y k vecinos más cercanos

Dos modelos básicos para los dos tipos de problema supervisado: una regresión lineal para predecir un número y k-NN para predecir una clase (o un número, con su versión de regresión). Cada uno con su métrica, y los dos dentro de un Pipeline.

Del problema al tipo de modelo

La pregunta guía es ¿qué valor quiero predecir? Un número continuo → regresión (precio de una vivienda, consumo de energía, tiempo de entrega). Una etiqueta → clasificación (compra / no compra, especie de flor, riesgo bajo / medio / alto). La métrica también cambia según el objetivo.

Regresión lineal simple

  • Un predictor x explica una respuesta numérica y con una recta: ŷ = β₀ + β₁x.
  • β₀, intercepto (modelo.intercept_): el valor predicho cuando x = 0. Puede ser necesario para la cuenta y no tener sentido práctico (una nota con 0 horas de estudio).
  • β₁, pendiente (modelo.coef_[0]): cuánto cambia y, en promedio, por cada unidad más de x. «Si β₁ = 5,3, una hora más de estudio se asocia con 5,3 puntos más de nota, dentro del rango observado».
  • Residuo: e = y − ŷ, la diferencia entre lo observado y lo predicho.
  • Una asociación lineal no prueba causalidad. Revisar residuos, atípicos, rango de aplicación y desempeño con datos no usados para entrenar.
from sklearn.linear_model import LinearRegression
from sklearn.metrics import mean_squared_error

X = df[["horas"]]       # doble corchete: X tiene que ser una tabla (2D)
y = df["nota"]          # un corchete: y es un vector (1D)
X_train, X_test, y_train, y_test = train_test_split(X, y, test_size=0.25, random_state=42)

modelo = LinearRegression()
modelo.fit(X_train, y_train)                       # ajusta intercepto y pendiente
y_pred = modelo.predict(X_test)
rmse = mean_squared_error(y_test, y_pred) ** 0.5   # o root_mean_squared_error(...)
print(modelo.intercept_, modelo.coef_[0], rmse)

RMSE: el error típico, en la unidad del objetivo

  • RMSE = √[(1/n) Σ(yᵢ − ŷᵢ)²] (raíz del error cuadrático medio). Se expresa en la misma unidad que y: RMSE = 4 puntos es «un error típico de unos 4 puntos de nota».
  • Al elevar al cuadrado, penaliza más los errores grandes. Más bajo es mejor, pero se compara con la escala del objetivo y con un modelo base (por ejemplo, predecir siempre el promedio).
  • En el proyecto de Airbnb se suman MAE (error absoluto medio, también en la unidad de y) y R² (proporción de la variación explicada: 1 es perfecto, 0 es lo mismo que predecir el promedio).

k vecinos más cercanos (k-NN)

  • Para un caso nuevo: 1 escalar las variables, 2 elegir k, 3 calcular la distancia a todos los casos de entrenamiento, 4 votar la clase más frecuente entre los k más cercanos (en regresión: promediar su valor).
  • La escala importa: k-NN mide distancias, así que una variable con números grandes (ingresos en miles) domina a una con números chicos (edad). Por eso el StandardScaler va antes, dentro del Pipeline.
  • fit en k-NN casi no «aprende» parámetros: guarda los datos de entrenamiento. El trabajo se hace al predecir.
  • Elegir k: uno muy chico se deja llevar por el ruido; uno muy grande suaviza de más. Se comparan varios con validación cruzada, no por intuición.
  • KNeighborsClassifier para etiquetas; KNeighborsRegressor para números (como el precio de Airbnb). weights="distance" da más peso a los vecinos más cercanos.

Métricas de clasificación

  • Accuracy = aciertos / total. Útil con clases balanceadas; engañosa si una clase domina.
  • Matriz de confusión: filas = clase real, columnas = clase predicha. La diagonal son los aciertos; fuera de ella, las confusiones. Se dibuja con ConfusionMatrixDisplay(matriz, display_labels=iris.target_names).plot(cmap="Blues").
  • Buena práctica: reportar accuracy junto con la matriz; con clases desbalanceadas, sumar precision, recall y F1.

Pipeline: imputar, escalar y modelar en un paso

Datos X → SimpleImputer (rellena faltantes) → StandardScaler → modelo → predicción ŷ. El imputador aprende la mediana con train, igual que el escalador, así que el Pipeline también evita la fuga en la imputación. Además simplifica la validación cruzada y permite guardar y compartir el flujo completo.

from sklearn.impute import SimpleImputer
from sklearn.neighbors import KNeighborsClassifier
from sklearn.pipeline import Pipeline

pipeline = Pipeline(steps=[
    ("imputar", SimpleImputer(strategy="median")),
    ("escalar", StandardScaler()),
    ("clasificar", KNeighborsClassifier(n_neighbors=5))])
pipeline.fit(X_train, y_train)
y_pred = pipeline.predict(X_test)
# para regresión: el mismo esquema con ("regresor", LinearRegression()) y RMSE

En una regresión lineal con una sola variable escalar no cambia las predicciones, pero mantiene el flujo homogéneo.

Mapa de decisión

Objetivo numéricoModelo inicial: regresión lineal. Métrica principal: RMSE. Diagnóstico: residuos y gráfico real contra predicho.
Objetivo categóricoModelo inicial: k-NN. Métrica principal: accuracy. Diagnóstico: matriz de confusión.

Regla de oro: la métrica no reemplaza mirar el problema. Comparar contra una línea base, revisar errores concretos y explicar qué significa el resultado para la decisión.

Errores frecuentes

  • Usar la prueba para entrenar → separar antes de ajustar cualquier transformación.
  • No escalar en k-NN → StandardScaler dentro del Pipeline.
  • Elegir k por intuición → comparar valores con validación cruzada.
  • Mirar solo accuracy → sumar la matriz de confusión y métricas por clase.
  • Extrapolar la recta → limitar las conclusiones al rango observado.
  • Confundir predicción con causalidad → hablar de asociación.
  • df["horas"] como X: es 1D y fit da ValueError: Expected 2D array. Va df[["horas"]].
  • KNeighborsClassifier para un precio: si y es un número continuo, va KNeighborsRegressor.

Actividad integradora de la clase. Caso A: predecir el consumo eléctrico diario según la temperatura media → X = temperatura, y = consumo, regresión lineal, RMSE, gráfico de dispersión con la recta. Caso B: clasificar clientes en «compra / no compra» con edad e ingresos → escalar porque edad e ingresos tienen escalas muy distintas, probar varios k impares con validación cruzada, la matriz muestra si el modelo falla más con los que compran o con los que no, y la accuracy no alcanza si casi nadie compra.

Clase 14

Git, GitHub y entornos reproducibles

Pasar de «funciona en mi equipo» a un proyecto trazable, revisable y repetible: versionar con Git, colaborar con GitHub (ramas y pull requests), aislar las dependencias en un entorno virtual y escribir notebooks que corran de punta a punta. El principio rector: cada resultado tiene que poder vincularse con una versión concreta del código, los datos y el entorno.

¿Qué problema resuelve?

  • «final_v7_ahora_si.ipynb»: no hay una historia confiable del análisis.
  • Resultados distintos: el notebook se ejecutó en otro orden o con otras versiones de las librerías.
  • Datos pesados o sensibles: el repositorio crece o expone información que no debe publicarse.
  • Cambios simultáneos: dos personas editan el mismo notebook y aparecen conflictos.

Git y GitHub no son lo mismo

GitEl motor de versiones: se instala en la computadora, registra «fotos» del proyecto (commits), permite ramas y fusiones, funciona sin conexión. La historia vive en la carpeta oculta .git (no se toca a mano).
GitHubLa plataforma colaborativa: aloja una copia remota, agrega pull requests y revisión, Issues, Projects, Actions (tests automáticos), permisos, releases. Se sincroniza con push, pull y fetch.

Vocabulario mínimo

  • Repositorio: la carpeta del proyecto más toda su historia. Commit: una foto guardada, con autor, fecha y mensaje. Staging (área de preparación): la «sala de espera» de lo que entra en el próximo commit.
  • Rama (branch): una línea de trabajo paralela para probar sin tocar main. Merge: unir una rama con otra. Fast-forward: si main no cambió, la fusión solo «adelanta» el puntero, sin commit de merge.
  • Conflicto: dos ramas cambiaron las mismas líneas y Git pide decidir. Pull request (PR): el pedido para fusionar una rama, donde se explica el cambio y un compañero lo revisa.
  • Etiqueta (tag): un nombre fijo para un commit importante (v0.1, v1.0). La anotada (git tag -a) guarda además un mensaje, autor y fecha.

Modelo mental: tres zonas

directorio de trabajo   (editás .py, .ipynb, README.md)
      │  git add archivo          ← add SELECCIONA
      ▼
área de preparación     (lo que va al próximo commit)
      │  git commit -m "..."      ← commit REGISTRA
      ▼
repositorio local       (historia confirmada)
      │  git push                 ← push PUBLICA
      ▼
remoto (GitHub)         (historia compartida)

git status  ← OBSERVA en qué zona está cada cambio

Leer git status: si un archivo aparece como modified pero no bajo «Changes to be committed», el cambio está en la carpeta de trabajo y no en el staging: falta git add, y si se hace el commit no lo incluye.

  • Antes del primer push: revisar .gitignore, credenciales, tamaño de los archivos y datos personales.
  • Git no versiona carpetas vacías: se deja un .gitkeep adentro para conservarlas.

Commits que explican una decisión

  • Un commit es chico, coherente y reversible. El mensaje dice la intención con un prefijo: feat: (funcionalidad nueva), fix: (corrección), chore: (configuración o mantenimiento). Bien: «feat: añade validación de valores nulos». Débil: «update notebook». Riesgoso: «modelo final + datos + secreto».
  • Checklist antes de commitear: el código corre, no hay secretos, el diff se entiende y el mensaje describe la intención.

Ramas y pull requests: experimentar sin romper main

  1. Crear la rama: git switch -c feature/eda-precios (crea y se pasa a ella).
  2. Trabajar y confirmar: commits chicos, notebook limpio.
  3. Abrir el pull request: objetivo, evidencia (qué se probó) y riesgos.
  4. Revisar y fusionar: otro integrante verifica código, datos, entorno y resultados; idealmente corren tests automáticos (GitHub Actions). Después git switch main + git pull origin main y se borra la rama.

Estrategia para un equipo: main protegida (nadie hace push directo, solo entra por PR aprobado), una rama por tarea (feature/ingestion, feature/limpieza, feature/modelado), ramas cortas y fusiones frecuentes (traer seguido los cambios de main), y módulos separados para que dos personas no editen el mismo archivo. Para equipos chicos alcanza con main + ramas de tarea (una rama develop es opcional).

Conflictos en un notebook

Un .ipynb por dentro es un JSON enorme (código, salidas, imágenes, metadatos): las marcas de conflicto (<<<<<<<, =======, >>>>>>>) pueden romperlo. Procedimiento seguro:

  1. No resolver a ciegas ni borrar una versión entera: respaldar las dos (git show main:analisis.ipynb > analisis_main.ipynb).
  2. Comparar por celda con una herramienta que entienda notebooks: nbdime (nbdiff, nbmerge) o el diff de Jupyter / VS Code.
  3. Hablar con la otra persona y decidir qué celdas quedan.
  4. Reejecutar de cero y verificar los resultados.
  5. Recién ahí git add y git commit.

Para prevenirlos: la lógica en .py, cada persona en notebooks distintos y salidas limpias antes de commitear.

Entornos virtuales: aislar dependencias

  • Un entorno virtual (.venv) es una instalación de Python aislada por proyecto: un proyecto con pandas 2.1 no choca con otro que usa pandas 3.0.
  • .venv/ no se versiona (es pesada y depende de cada máquina: se reconstruye). Sí se versiona el archivo de dependencias: requirements.txt, pyproject.toml o environment.yml.
  • Con el entorno activo el prompt muestra (.venv); python -c "import sys; print(sys.executable)" confirma que se usa el Python del entorno. python -m pip asegura que se usa el pip de ese intérprete.
  • pip freeze anota todas las versiones instaladas, también las dependencias de las dependencias: por eso el archivo sale largo (con Jupyter, muy largo).
python -m venv .venv                    # crear el entorno (una vez)
.venv\Scripts\activate                  # activar en Windows (PowerShell: .\.venv\Scripts\Activate.ps1)
source .venv/bin/activate               # activar en macOS / Linux
python -m pip install pandas jupyter matplotlib
python -m pip freeze > requirements.txt # anotar versiones exactas
pip install -r requirements.txt         # en otra máquina: reconstruir el entorno
deactivate                              # salir del entorno

Secuencia correcta de trabajo: 1) activar el entorno, 2) instalar las dependencias (si se instala antes de activar, van al Python global), 3) ejecutar el notebook desde el inicio, 4) verificar los resultados. Documentar también la versión de Python.

Reproducibilidad de punta a punta

Un resultado se reproduce si están coordinadas cuatro versiones: código (un commit o tag), datos (una copia fechada o su hash), entorno (dependencias fijadas) y ejecución (parámetros y semilla). Prueba de fuego: clonar el repositorio en un entorno limpio, instalar las dependencias, conseguir los datos autorizados y regenerar el resultado sin pasos manuales escondidos. Los hitos se marcan con etiquetas: v0.1-eda, v0.2-modelo, v1.0-informe.

Datos grandes y sensibles

  • Tamaño: Git está pensado para texto chico. GitHub rechaza archivos de más de 100 MB y cada versión de un CSV queda para siempre en el historial.
  • Privacidad: cualquiera con acceso al repo vería los datos, aunque se borren después. Puede violar normas de protección de datos (en Argentina, la Ley 25.326).
  • Qué hacer: data/ en .gitignore; el archivo en un almacenamiento con control de acceso; versionar la referencia al dato, no el dato (con DVC, o un script de descarga con checksum); documentar en el README cómo se obtiene; una muestra anonimizada para desarrollar; credenciales en .env. Git LFS sirve para archivos grandes pero no resuelve el problema de privacidad.

Errores típicos

  • Commitear sin git add: el cambio queda afuera del commit.
  • Subir .venv, __pycache__, .env o datos en vez de requirements.txt.
  • Creer que borrar un secreto del último commit alcanza: sigue en el historial; hay que revocarlo.
  • Confundir Git con GitHub: Git funciona sin GitHub.
  • Resolver un conflicto de notebook a mano en el JSON o aceptando una versión entera sin mirar.
  • Instalar antes de activar el entorno.
  • Crear el repo de GitHub con README cuando ya existe uno local: las historias divergen en el primer push.
  • Mensajes vagos («cambios varios», «update»).

Ejemplo comentado: una limpieza reutilizable

import pandas as pd

def limpiar_ventas(df: pd.DataFrame) -> pd.DataFrame:
    """Devuelve ventas válidas, no negativas y sin id repetidos."""
    requeridas = {"id", "producto", "venta"}
    faltantes = requeridas - set(df.columns)     # diferencia de conjuntos
    if faltantes:                                # un conjunto vacío vale False
        raise ValueError(f"Faltan columnas: {faltantes}")
    limpio = df.copy()                           # no modifica la entrada
    limpio["venta"] = pd.to_numeric(limpio["venta"], errors="coerce")  # "ERROR" → NaN
    limpio = limpio.dropna(subset=["venta"])     # saca los no numéricos
    limpio = limpio[limpio["venta"] >= 0]        # saca los negativos
    limpio = limpio.drop_duplicates(subset="id", keep="first")
    return limpio.reset_index(drop=True)

Tres partes: validación estructural (el DataFrame trae las columnas del contrato), transformación segura (trabaja sobre una copia y convierte los errores en nulos) y una regla verificable (el resultado no tiene id repetidos, nulos ni ventas negativas). Con los datos de las guías (ids 101 a 107, con un 102 repetido, un −75, «ERROR» y «ABC») quedan los ids 101, 102, 105 y 107.

El orden importa. La diapositiva quita duplicados antes de convertir y filtrar; los programas de la guía lo hacen después. Si la primera fila de un id repetido es inválida, dan distinto: con id = [1, 1, 2] y venta = ["ERROR", 100, 50], deduplicar primero conserva el «ERROR», lo descarta y pierde el id 1 (queda [2]); filtrar primero conserva la venta válida de 100 (queda [1, 2]). Filtrar y después deduplicar es lo más seguro.

Qué probar: la pirámide

  • Base, muchos tests rápidos y específicos: funciones puras y reglas de negocio (limpiar_ventas, calcular_total).
  • Medio: integración entre módulos y archivos chicos.
  • Cima, pocos y más lentos: el notebook o el flujo completo.
  • Una prueba tiene que fallar por una razón clara y ayudar a encontrar el defecto.

assert: la base de todo

assert condicion, "mensaje" es una instrucción de Python (no hace falta instalar nada): si la condición es True sigue; si es False corta con AssertionError y el mensaje. Sirve para ejemplos y verificaciones simples, pero Python la saltea si se ejecuta con -O: no se usa para validar datos de usuarios ni reglas de seguridad (para eso, if + raise).

pytest: funciones test_ y assert

  • pytest descubre solo los archivos test_*.py y, adentro, las funciones test_*. Se instala aparte (pip install pytest) y se corre con pytest -q o python -m pytest -v.
  • Cada test sigue Arrange – Act – Assert: armar datos mínimos que representen el caso, ejecutar una unidad y comparar con un resultado preciso.
  • with pytest.raises(ValueError, match="Faltan"): comprueba que el código lanza esa excepción y que el mensaje contiene «Faltan». Si no la lanza, el test falla.
  • @pytest.mark.parametrize("valores, esperado", [...]) corre el mismo test con varios casos.
  • @pytest.fixture: una función que prepara datos reutilizables; el test la pide poniendo su nombre como parámetro y pytest la ejecuta antes de cada test (datos nuevos cada vez).

unittest: la alternativa de la biblioteca estándar

  • Viene con Python. Las pruebas son métodos de una clase que hereda de unittest.TestCase.
  • setUp(self) se ejecuta antes de cada test (como una fixture); tearDown, después. Los datos se guardan en self.
  • Aserciones propias: assertEqual, assertTrue, assertListEqual, assertRaises.
  • Se corre con unittest.main(verbosity=2) al final del archivo o con python -m unittest -v.
pytestSintaxis corta con assert, fixtures flexibles, parametrización directa, plugins, descubrimiento simple. Hay que instalarlo. Ideal para cursos, proyectos de datos y equipos que priorizan la legibilidad.
unittestIncluido en Python, estilo de clases, setUp/tearDown, aserciones específicas, familiar en el mundo xUnit. Para depender solo de la biblioteca estándar.

No repetir código (DRY)

Si el mismo bloque de limpieza está copiado en cuatro notebooks y aparece un error, hay que arreglarlo cuatro veces (y alguna se olvida): viola DRY (Don't Repeat Yourself). La solución es la de toda la clase: una función en un módulo, importada desde los notebooks y cubierta por tests.

Flujo recomendado

1 Explorar (notebook chico) → 2 Extraer (funciones a src/) → 3 Documentar (README y docstrings) → 4 Probar (pytest o unittest) → 5 Reejecutar (notebook limpio) → 6 Compartir (código, entorno y resultados). Criterio de salida: otra persona puede instalar, ejecutar, verificar y explicar el resultado sin depender del autor.

Errores típicos

  • Archivo o función sin el prefijo test_: pytest no los encuentra y «pasan» 0 tests.
  • Un test que falla no siempre es un error del código: puede estar mal la expectativa (en las guías, el test espera 5 filas y la limpieza correcta da 4).
  • Probar con datos que no cubren el caso: sin un duplicado o un texto en la entrada, el test no verifica la regla.
  • Modificar la entrada dentro de la función (sin df.copy()): se rompen otros tests que usan los mismos datos.
  • Deduplicar antes de filtrar cuando la primera fila de un id puede ser inválida.
  • Usar assert para validar datos en producción: con python -O desaparece.
  • Olvidar if __name__ == "__main__":: al importar el módulo desde un test, se ejecuta el programa entero.

Cómo encarar un «código con errores»

  • Leé el objetivo antes que el código: ¿qué tendría que producir?
  • Revisá línea por línea: nombres de columnas (¿coinciden con los del DataFrame?), nombres de métodos y parámetros (¿bien escritos? ¿en plural?), paréntesis y la fórmula (¿es la cuenta correcta?).
  • Distinguí dos tipos de error. Los que rompen el programa (da un error y frena) y los lógicos (corre, pero el resultado está mal). Los segundos son más peligrosos porque no avisan.
  • En el espacio de diagnóstico escribí qué falla, por qué y cómo se corrige, con el resultado esperado.

Tres ideas que se repiten en todos los ejercicios

  • Un método se ejecuta con paréntesis. df["x"].mean no calcula nada: devuelve el método (<bound method …>) y, si se usa en una cuenta, da TypeError.
  • Los parámetros se escriben exactamente como pandas los espera: columns, no column; values, no value; include_groups, no include_group. Uno mal escrito da TypeError: unexpected keyword argument.
  • Los nombres de columnas se copian tal cual: "ciudades" en vez de "ciudad" da KeyError. Y salvo el primero, los argumentos van con nombre: un valor posicional puede caer en el parámetro equivocado sin error.

Errores típicos de un vistazo

  • Método sin paréntesis: .mean, .sum → .median(), .sum().
  • Nombre de método mal escrito: describes() → describe() (AttributeError).
  • Nombre de columna distinto al real: "ciudades" → "ciudad" (KeyError).
  • Parámetro en singular: column=, value=, include_group= → plural (TypeError).
  • aggfunc inexistente: "average" → "mean".
  • Percentil como porcentaje: quantile(25) → quantile(0.25) (ValueError).
  • Fórmula equivocada: q1 + q3 → q3 - q1; altura * 2 → altura ** 2 (error lógico).
  • Tipo de dato equivocado: fill_value="0" → fill_value=0.
  • Faltante tratado como cero: sum sobre un grupo vacío → sum(min_count=1) y justificar la decisión.
  • Labels ≠ intervalos: 5 labels con 5 bordes → 4 labels; y pasarlos con nombre.
  • División por cero: suma / pesos → if pesos == 0: np.nan.
  • Y/o con Series: and/or → &/| con cada condición entre paréntesis.
  • Sin sangría en el cuerpo de una función → IndentationError.
