# IAgram Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build `iagram.html`, a self-contained mobile-feed page where each materia is an Instagram-style "perfil" and each key concept from a clase is a "post", with a working pilot of real content for Ética (7 clases, 21 posts).

**Architecture:** A single-file mini-SPA (no framework, no build step — same pattern as `etica.html`/`index.html`). Two views (`Explorar` = grid of perfiles, `Perfil` = header + scrollable feed) toggled with plain JS and a `#perfil=<id>` hash router (`hashchange`/`popstate` via the hash itself, so browser back/forward works). All data (`PERFILES`, `POSTS`) is embedded in inline `<script>` — no separate data files, no backend, no `fetch`.

**Tech Stack:** Plain HTML/CSS/JS (ES5-compatible, matches the rest of the site's inline scripts). No dependencies, no dev server required — the page opens directly as a local file or via any static server.

**Spec:** [docs/superpowers/specs/2026-09-27-iagram-design.md](../specs/2026-09-27-iagram-design.md)

## Global Constraints

- Reuse the existing design tokens verbatim (`--papel*`, `--tinta*`, `--linea*`, `--u1..u4`, `--u1-suave..u4-suave`, `--display`, `--body`, `--mono`) — no new color palette.
- Reuse the exact dark-mode mechanism: `data-tema` attribute on `<html>`, persisted under the **same** `localStorage` key `ia-tema`, so toggling theme in IAgram matches whatever is already set on the rest of the site.
- No backend, no Supabase, no `localStorage`-persisted likes/saves — purely visual feed (explicit user decision).
- Single new file `iagram.html`, self-contained (inline `<style>` and `<script>`, no external CSS/JS files created).
- Feed column is `max-width: 470px`, centered, and stays that width on desktop too (intentional — it's meant to feel like a phone app, not a responsive site section).
- Respect `prefers-reduced-motion` and `:focus-visible` the same way the rest of the site does.
- Do not touch glosario, flashcards, "confusiones típicas", or the simulacro in any materia page.
- Post captions must be original phrasing (not copy-pasted from the apunte) — they are hooks that link back to the full section via `href="<materia>.html#cN"`.

- [ ] **Step 2: Add the post-rendering engine**

  function badgeDePost(tipo){
    if(tipo === "trampa") return "⚠ Error típico";
    if(tipo === "caso") return "📌 Caso real";
    if(tipo === "parcial") return "★ Para el parcial";
    return "";
  }

  function crearPost(perfilId, post){
    var perfil = PERFILES[perfilId];
    var badge = badgeDePost(post.tipo);
    var art = document.createElement("article");
    art.className = "post post-" + post.tipo;
    art.innerHTML =
      '<header class="post-header">' +
        '<span class="post-avatar" data-u="' + perfil.unidad + '">' + perfil.nombre.charAt(0) + '</span>' +
        '<span class="post-usuario">' + perfil.usuario + '</span>' +
        '<span class="post-clase">Clase ' + post.clase + '</span>' +
      '</header>' +
      '<div class="post-tarjeta" data-u="' + perfil.unidad + '">' +
        (badge ? '<span class="post-badge">' + badge + '</span>' : '') +
        '<p class="post-tarjeta-titulo">' + post.titulo + '</p>' +
      '</div>' +
      '<div class="post-caption">' +
